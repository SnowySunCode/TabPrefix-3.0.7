# Проверки TabPrefix 3.0.4

Production-код: 109 Java-файлов, Java 8 bytecode. Все 17 Java-прогонов прошли: 2 856 039 assertions, включая повторные измерения пикселей и метрик. Также прошли 310 OpenGL-проверок, 129 + 61 + 9 DOM/HTTP-проверок и 28 + 14 проверок очереди сохранения/синхронизации.

Совместимость: три производные Bukkit API-поверхности, старый/новый pack API и десять семейств packet fixtures прошли. Проверена самостоятельная работа без LuckPerms API. Все 169 собственных классов итогового JAR имеют Java 8 bytecode. Лицензия проекта, 16 вложенных dependency notices и TTF сохранены без изменений. ZIP проверен по CRC и SHA256SUMS; чистая offline-пересборка с заранее подготовленными зависимостями сверена по содержимому всех записей JAR без учёта ZIP-времени.

## Новое в 3.0.4

- Подложки полной строки TAB проверяются для 1–4 колонок с головами и без них. Независимые PNG-метрики сверяются с native name/head/ping шириной; фон доходит до правого края, сохраняет окно головы 8 × 8 и не увеличивает advance имени.
- Составной скорборд восстанавливается из PNG при Y = −512 / −180 / −110 / 120. Плотность HD остаётся 4, сравнивается каждый значимый пиксель. Короткие последние полосы имеют допустимый bitmap ascent. Проверены переключение качества и чтение сохранённого пака.
- Крупный шрифт 32 GUI px проверяется по исходному TTF: площадь штриха `j` сравнивается с целым эталоном, включая отрицательный bearing и нижний вынос. При растеризации сохранён однопиксельный ореол сглаживания за GlyphVector bounds.
- GPU-проверка компилирует VSH/FSH из настоящего ZIP с соответствующими include-файлами Minecraft на Mesa/EGL. Проверяются все четыре угла глифа, одинаковые границы для фильтра, отсутствие тени у подложки, сохранение тёмного текста, отсутствие влияния на обычные изображения и соседние глифы. Толщины 0,25 / 0,5 / 0,75 / 1 / 1,5 / 2 измеряются после отрисовки при GUI scale 1 / 2 / 3 / 4.
- DOM/HTTP-проверки используют production JS и настоящий HTTP/SQLite. Новые сценарии покрывают режим полной строки/карточки, видимость поля отступа, наличие головы/пинга в предпросмотре и сохранение `tabHeads`/`hudQuality`. Сохраняются предыдущие проверки футера, рисования, автосохранения и новых сессий.

Счётчики assertions включают повторные проверки пикселей и метрик, а не число независимых пользовательских сценариев. OpenGL-проверка не запускает Minecraft. Chromium и игровой клиент в среде выпуска отсутствуют: скриншоты пользователя просмотрены, финальная игровая композиция здесь не проверялась. Низкое разрешение исходного фото/GIF не повышается как у векторных фигур.

Команды: `bash test.sh --offline`, `bash test-compatibility.sh`, `node tests/polish-dom.mjs`, `node tests/prefix-dom.mjs`, `node tests/session-dom.mjs`, `node tests/live-save.mjs`, `node tests/state-sync.mjs`. Дополнительно `python3 tests/hud-gpu.py .`: Linux EGL/OpenGL, NumPy и Pillow; include-файлы берутся из фиксированных выпусков mcmeta и сохраняются в `.build`.

## Футер и автоматическое применение в 2.8.2

- Production DOM: выключенный футер включается при вводе из инспектора; правка первого кадра сохраняет второй; неизменившиеся опросы не запускают перерисовку.
- Production DisplayController: кадры футера идут при сломанном setter Header и медленном общем интервале. Ошибка getter Footer не останавливает дальнейшие записи; Header того же игрока и Footer другого игрока остаются независимо читаемыми.
- Реальный HTTP/SQLite: прямое применение без кода, повторная запись, конфликт старой версии, более восьми последовательных сейвов, проверка отозванных прав, запрет управляющих символов, повторное использование изображения и глифов.
- Production prefix DOM/HTTP: автоматическое применение, ввод во время ответа с задержкой, сохранение фокуса, получение чужой правки, выбор при конфликте, ввод во время загрузки картинки, применение параметров картинки и сохранность предыдущего источника после новой загрузки.
- Общая Studio-группа: изменение одной группы сохраняет префикс остальных, остальные кадры, суффикс и цвет. SQLite trigger имитирует сбой обновления дизайна; проверяются отказ записи и откат SQL/публичных snapshot, затем повтор после снятия сбоя.

## Автосохранение и футер в 2.8.1

- Production DisplayController продолжает прокрутку, когда независимый Bukkit fixture возвращает футер без отправленного `§r`; статический текст не отправляется повторно. Это воспроизводит ошибку сравнения исходной строки с нормализованным getter, без запуска настоящего сервера.
- Реальный HTTP/SQLite: повтор того же документа не увеличивает ревизию; другая устаревшая правка получает 409. Условный state endpoint не возвращает весь документ без изменений, сохранённый предпросмотр использует текущую ревизию.
- JavaScript queue: 27 проверок ввода во время запроса, объединения разных полей, перемещения строк по ID, совпавших правок, выбора версии без потери независимых полей, автоматического повтора после разрыва связи, остановки повторов неверного документа и восстановления черновика.
- Production ResourcePackService: обычный текст повторно использует активный pack без задачи сборки; очередь изменения координат видна сразу, две быстрые правки публикуют один настоящий pack с последним макетом.
- Production DOM/HTTP-сценарии: автоматическое сохранение футера, ввод при задержке ответа 800 мс, автоматическое получение серверной правки, выбор версии при совпавшем поле, undo/redo без отката чужих независимых правок, локальная смена кадров между API-опросами. Остальные сценарии фигур, групп, босса и календаря также выполняются.

## Новое оформление

- Java-тесты читают настоящие PNG: заливку, альфа-канал, градиент, эллипс, многоугольник и свободный контур. Проверены пределы размеров/точек/числа слоёв, дубликаты и привязки к существующим строкам.
- Для 1.13, 1.19 и 1.21 собираются настоящие resource-pack ZIP. Независимое чтение пикселей проверяет ширину глифов и законность bitmap-провайдеров. Проверен полный макет: 80 ячеек, по 12 баннеров шапки/футера, 15 строк скорборда и 12 экранных блоков. Коды не пересекаются между собой и со spacers.
- Текст, жирное начертание и графические префиксы накладываются с точной конечной шириной. Проверены отступы баннеров, обрезка текста, перезапуск, устаревшая геометрия/цвет и читаемый 1.12 fallback.
- Production DisplayController на native API fixtures отправляет новую графику футера и текст свободного макета после успешной доставки пака; до доставки остаётся читаемый персонализированный footer. Веб-превью не заменяет текст приватными символами.
- DOM/HTTP-сценарии проверяют открытие вкладки, пресеты, изменение фигуры, обработчики перетаскивания и рисования, копирование/удаление, выравнивание строки, отбраковку неверного кегля, баннер TAB, оформление столбца, реальное SQLite-сохранение, защищённый PNG API, удаление привязок и undo, перевод и сохранение SVG-иконки.

Счётчики Java-набора включают повторные проверки каждого глифа и его пиксельных метрик; это не число уникальных пользовательских сценариев.

## Повторение

```bash
bash test.sh
bash test-compatibility.sh
node tests/live-save.mjs .
node tests/state-sync.mjs .
node tests/session-dom.mjs .
node tests/polish-dom.mjs .
node tests/prefix-dom.mjs .
```

DOM-набор использует включённый в архив LinkeDOM под MIT-лицензией и production-файлы редактора. Он проверяет обработчики и HTTP-запись, но не измеряет CSS-верстку, browser native drag-and-drop или GPU-отрисовку. Лицензия: `tests/vendor/linkedom-LICENSE.txt`. Это зависимость тестов; в JAR она не включена.

Для дополнительных браузерных проверок при установленных Playwright/Chromium сохранены `tests/editor-browser.cjs`, `tests/studio-browser.cjs`, `tests/dream-browser.cjs`. Для 3.0.1 эти старые сценарии не объявляются пройденными: Chromium отсутствует, часть сценариев относится к прежнему Apply/code потоку. Текущие проверки перечислены выше.

## Сборка и архив

Сверяются версия plugin.yml, наличие всех локальных редакторов и встроенного шрифта, Java bytecode, неизменность оригинальной лицензии, CRC ZIP/JAR и SHA256SUMS. Финальный архив распаковывается в чистый каталог, затем выполняется offline-сборка с теми же проверенными зависимостями. Сравниваются байты всех JAR entries; timestamps контейнера JAR не сравниваются.

## Что требует проверки в игре

Minecraft-клиент, настоящий Spigot/Paper/Purpur и смешанные версии через ViaVersion не запускались. Необходимо проверить фигуры, высоту баннеров/ширину ячеек TAB, шрифтовую панель с разными GUI Scale, длинные строки, принятие/отказ пакета, совместное использование HUD другими плагинами, выбранного настоящего босса и заданное расписание. Загрузочные ограничения 1.12 сохраняются: панель без цифр в открытом TAB; свободный XY и выборочное скрытие чисел старого стандартного sidebar не добавлены.
