# TabPrefix 3.0.7

Плагин оформления Minecraft Java 1.12.x–1.21.x и 26.1–26.3: TAB, префиксы и суффиксы, name tags, скорборды, боссбары, изображения/GIF, ресурс-паки и веб-редакторы. Автор: **SnowySunCode**. Java target 8. Архив содержит 112 production Java-файлов и собранный `dist/TabPrefix.jar`. LuckPerms — необязательная интеграция; плагин работает самостоятельно.

## Ровные контуры в 3.0.7

Скруглённые панели и прямоугольники рассчитывают площадь круглого края в каждом пикселе. Заливка и рамка используют общее покрытие и одну прозрачность: полупрозрачная щель и второй контур на их стыке убраны. Толщина рамки сохраняется при изменении ширины панели. Для остальных фигур объединены маски заливки и обводки; отдельные слои по-прежнему накладываются друг на друга.

HD-фигуры обычно готовятся с плотностью 8. При большом макете автоматически остаётся плотность 4, чтобы ограничить память исходных кадров; текст и фото сохраняют собственные пути. Фрагменты подложек и экранных картинок получают реальные соседние пиксели по краям. Шейдер назначает каждый выходной пиксель одному фрагменту и усредняет цвет с прозрачностью, поэтому дробное положение не образует светлые полосы, щели и двойное наложение. Исправлен небольшой сдвиг выборки из-за нативного отступа UV.

Renderer 9 автоматически требует новый пак. Остановите сервер, замените JAR, запустите сервер и примите обновлённый ресурс-пак. Всё остаётся в одном серверном плагине. HD-фильтрация требует 1.17+; на старых клиентах и в режиме совместимости действуют ограничения их bitmap/Unicode-отрисовки. [Изменения](docs/CHANGELOG-3.0.7.md) · [Проверки](docs/VALIDATION.md).

## Качество текста в 3.0.6

Жирный текст HUD и компактного TAB использует собственное начертание DejaVu Sans. Код `§l` выбирает готовый жирный глиф вместо второй смещённой копии буквы; ширина измеряется по доставленному начертанию. Второй приватный Unicode-план сохраняет прежний бюджет макета. Обычные и жирные буквы, сброс цвета, обрезка строки, общие профили и веб-предпросмотр используют согласованные коды и метрики.

В HD-пути текст хранит исходное покрытие пикселей вместе с полем расстояний до контура. При уменьшении фильтруется покрытие; при увеличении шейдер сглаживает границу по размеру выходного пикселя. Глиф получает свободный край, чтобы выносные элементы и курсив не обрезались. Расчёт контура кэшируется по шрифту, начертанию и размеру, а позиции строк меняют только служебную разметку. Исправлена обработка прозрачности приватного RGBA-текста в grayscale-ветке новых шейдеров.

Renderer 8 автоматически требует новый пак при обновлении. Перезапустите сервер с новым JAR и примите обновлённый ресурс-пак; прежние глифы сохраняют свои метрики до его загрузки. Максимальное сглаживание произвольного HUD требует HD-режима на 1.17+; bitmap-путь старых клиентов и режим совместимости сохраняют ограничения клиента. [Изменения](docs/CHANGELOG-3.0.6.md) · [Проверки](docs/VALIDATION.md).

## HD в 3.0.5

HD HUD работает на Minecraft 1.17–1.21.11 и 26.1–26.3: текст, скорборд, фигуры, оформление TAB/header/footer, экранные PNG/GIF и изображения в компактном TAB. Десять вариантов шейдера учитывают изменения fog/lightmap, GUI, grayscale и интерфейса 26.3. Плотность 4 не зависит от вертикального смещения; фильтрация площади пикселя сохраняет тонкие линии и изолирует соседние глифы. Ускорено повторное использование одинаковых фрагментов при пересборке.

На 1.12 PNG/GIF используют Unicode-страницы 1024 × 1024 с неизменной геометрией и назначениями глифов. Это повышает разрешение текстур, но не добавляет отсутствующие возможности произвольного HUD. На 1.13–1.16 сохраняется bitmap-режим с доступной плотностью; исправлено обрезание краёв букв. Полный shader HD произвольного HUD на 1.12–1.16 серверный плагин без клиентского расширения не предоставляет.

Полные строки TAB сохраняют посадку 3.0.4: фон охватывает имя и пинг, учитывает головы и не увеличивает ширину таблицы повторно. Для стороннего шейдерного пака остаётся режим совместимости. Низкое разрешение исходного фото/GIF не превращается в дополнительную детализацию.

После замены JAR нужен перезапуск сервера и новый ресурс-пак. Renderer 7 заставляет старый HUD-пак автоматически пересобраться при включённой автоматике. [Совместимость HD](docs/HD-COMPATIBILITY.md) · [Изменения](docs/CHANGELOG-3.0.5.md) · [Проверки](docs/VALIDATION.md).

## Переработка TAB и редакторов в 3.0.2

TAB по умолчанию занимает место по содержимому: вместо 80 пустых ячеек отправляются только активные. Ширина надписей, картинок и подложек ограничена шириной колонок; шапка и футер имеют отдельный предел высоты. Избыточная информация сменяется целыми блоками. Для точного ручного макета остаётся режим полной сетки.

В редакторе главный элемент — крупный предпросмотр с выбором ячейки нажатием. Исходная сетка убрана в раскрывающийся раздел, у инспектора есть закрытие. Переработаны панели, поля, отступы, поведение узкого экрана и Prefix Studio. PNG/GIF отображаются в предпросмотре; кадры догружаются с ограниченной очередью, последний готовый кадр остаётся видимым.

[Обновление и ограничения клиента](docs/CHANGELOG-3.0.2.md) · [Как работает сохранение](docs/EDITOR-SYNC.md).

## Исправления в 3.0.1

Редакторы открываются с единым снимком актуального состояния сервера: оформление TAB/скорборда/экрана, префиксы и суффиксы, каталоги групп и глифов, личные настройки и состояние пака. Изменения подхватываются автоматически. Черновики восстановятся и в новой вкладке того же браузера; старая версия не затирает более новые серверные поля.

Сохранённое изображение больше не выключается при вводе текста до загрузки превью. GIF показывает первый кадр сразу, остальные догружаются в фоне. Исправлены пустые кадры слишком узкой строки и временная потеря экранного текста; старые паки пересобираются под новую версию renderer. [Подробности и обновление](docs/CHANGELOG-3.0.1.md) · [Как работает сохранение](docs/EDITOR-SYNC.md).

## Изменения в 3.0.0

Prefix Studio объединяет текст, PNG/GIF и суффиксы: основной элемент и до 32 дополнительных элементов с каждой стороны имени, порядок, включение и интервалы. Сохранение всей композиции атомарное. Адаптивный TAB учитывает ширину кадров и высоту изображений, оставляет место между строками, а подложки ячеек расширяются под имя. Скорборд сохраняет буквы при изменении размера и пересборке пака; длинные строки можно прокручивать, показывать целиком или сокращать с многоточием.

Добавлены шесть тем редактора и собственная палитра JSON, шесть текстовых эффектов, девять якорей изображений, размеры холста и сдвиги. `/lptab design [group]` открывает Studio через тот же механизм групп, прав и сетевых ссылок, что `/lptab webeditor`. [Изменения и обновление](docs/CHANGELOG-3.0.0.md) · [Prefix Studio](docs/PREFIX-STUDIO.md).

## Нативный HUD и новые редакторы в 2.6.0

На **1.13+** вкладка **«Экран»** предлагает свободное размещение: включите переключатель, перетащите текст или картинку, задайте X/Y и размер, затем примените оформление. Плагин создаёт и доставляет обычный vanilla ресурс-пак со своими глифами и смещениями. Клиентские моды, OptiFine, ProtocolLib и отдельный HUD-плагин не нужны. Картинки используют кадры сохранённых PNG/GIF; текст сохраняет цвета, жирное и курсивное начертание.

В редакторе скорборда выбирается способ показа: **классический скорборд**, **панель без цифр** или **панель в TAB**. Панель без цифр рисуется через HUD и не создаёт objective/scores. Пока соответствующий ресурс-пак не загружен, она показывается в TAB footer; это также вариант для **1.12**. Классический sidebar продолжает обновляться без пересоздания; blank number format доступен на 1.20.3+ при подходящем API/адаптере.

**Граница 1.12:** графические префиксы и PNG/GIF работают через старые Unicode-страницы, но свободный XY-HUD и удаление числовой колонки именно у стандартного sidebar не реализованы. Без модов используется панель в открытом TAB. Ресурс-пак должен быть принят игроком; `ACCEPTED` ещё не включает графику — требуется `SUCCESSFULLY_LOADED`. Обычные цифры шрифта не заменяются.

Все встроенные веб-редакторы получили общий стиль, светлую/тёмную темы, векторные значки и поиск разделов по Ctrl/Cmd+K. В редакторе префиксов добавлены готовые варианты VIP/ADMIN/HELPER. CSS/JS входят в JAR и работают без CDN.

Собственные группы без LuckPerms задаются в приоритетах Studio; принадлежность определяется правом `tabprefix.group.<group>`. Из нескольких групп берётся первая в настроенном порядке. Без подходящего права используется `default`. При установленном и включённом LuckPerms сохраняются его контексты, metadata и события.

[Нативный HUD: настройка и границы](docs/NATIVE-HUD.md) · [Таб мечты и глифы](docs/DREAM-TAB.md) · [Изменения 2.6.0](docs/CHANGELOG-2.6.0.md) · [Совместимость](docs/COMPATIBILITY.md) · [Проверки](docs/VALIDATION.md). В 2.7 выполнены проверки Java/SQLite/HTTP, содержимого ZIP, моделей API и DOM-интерфейса. Chromium-сценарии включены в исходники для отдельного запуска. Реальный Minecraft-клиент и живые серверы в среде сборки не запускались.

## Display Studio

Суффиксы для групп, цвет имени, общий формат TAB и сортировка по перетаскиваемым приоритетам, весу LuckPerms, имени, группе, миру или задержке. Работает и в обычном TAB; есть личные переключатели. Новый шаблон «Спокойный TAB» оформляет список мягкими цветами и значками, сохраняя sidebar и боссбары. После обновления: `/lptab design` → «Спокойный TAB» → «Применить». Подробнее: [TAB-SUFFIXES.md](docs/TAB-SUFFIXES.md).

Оформление сервера настраивается в браузере без редактирования YAML:

1. Замените JAR на 3.0.7 при остановленном сервере и полностью запустите сервер.
2. Выполните `/lptab design` с правами администратора (`tabprefix.use` и `tabprefix.design`).
3. Выберите шаблон «Спокойный TAB», «Минимализм», «Неон» или «Классика», перетащите блоки и настройте текст, цвет, стиль и анимацию.
4. Изменения автоматически сохраняются и применяются. Дождитесь статуса «Сохранено · авто»; «Сохранить сейчас» или Ctrl/Cmd+S отправляет их сразу.

Включены sidebar до 15 строк, TAB header/footer до 12 строк каждый, компактный TAB по содержимому и полная исходная сетка 4 × 20 ячеек, обычный TAB, бегущие строки и смена кадров, текстовые/PNG/GIF-префиксы над головой, настройки видимости и столкновений. Есть отмена/повтор, перетаскивание мышью и касанием, кнопки перемещения, RU/EN, JSON-импорт/экспорт и серверный предпросмотр. Подробнее: [DISPLAY-STUDIO.md](docs/DISPLAY-STUDIO.md).

Игрок использует `/lptab settings` (`tabprefix.settings`, по умолчанию доступно): может отключить у себя sidebar, header/footer, макет TAB, префиксы над головой, суффиксы, сортировку и анимацию, включая GIF. Это не изменяет оформление для остальных.

Новая вкладка **«Боссбары»**: до 8 независимых полос с перетаскиванием мышью/касанием, дублированием и предпросмотром. Все 7 цветов, сплошной и 4 сегментированных стиля Minecraft, ручной процент со слайдером, здоровье/максимальное здоровье, еда, опыт до уровня, онлайн и своё значение из числовой подстановки. Таймер заполнения, обратный отсчёт и пульсация поддерживают повторение и скрытие после завершения; `{progress}` и `{remaining}` работают в тексте. Доступны анимация заголовка, показ одновременно/по очереди, фильтры миров и прав, затемнение неба, музыка босса и туман. Личные настройки содержат отдельный переключатель боссбаров. Подробнее: [BOSSBARS.md](docs/BOSSBARS.md).

Версия 2.6 читает документы оформления и настройки игроков из 2.1/2.2/2.3/2.4/2.5 без сброса. Схема базы остаётся 3; новые поля добавляются в существующие JSON-документы. Боссбары включаются при добавлении первой полосы в редакторе.

Оформление и личные настройки хранятся в существующей SQLite-базе; схема обновляется до версии 3. **Перед обновлением сохраните копию всей папки `plugins/TabPrefix` при остановленном сервере.** JAR 2.0.x не открывает схему 3; для возврата нужна копия базы. Новые оформления по умолчанию выключены; существующий флаг name tags учитывается при первом создании документа Studio.

## Реализовано

- Необязательный LuckPerms: контексты игрока, primary group или группа с максимальным весом, обновление по событиям. Собственные префиксы хранятся отдельно и не изменяют узлы LuckPerms.
- Текстовые override групп, MiniMessage и legacy, RGB, политика цветов/decorations/click/hover, безопасные подстановки.
- PNG, JPEG с EXIF orientation и GIF: прозрачность, offsets/disposal кадров, задержки в ticks, проверка реального формата и лимитов до обработки.
- «Таб мечты»: палитра элементов/картинок, мышь и touch, 80 ячеек, настройки блока, undo/redo, SQLite/JSON.
- Экран: FREE_XY (1.13+ и pack), TITLE/SUBTITLE/ACTION_BAR, текст/PNG/GIF, анимации и world/permission filters, личное отключение.
- Глифы и пак: пиксельный редактор 16×16, загрузка PNG/GIF, каталог постоянных assets, ZIP-download и импорт старого шрифта.
- Web editor EN/RU: загрузка и drag-and-drop, обрезка, contain/cover/stretch, pixel/smooth, upscale, отражение, поворот, яркость/контраст/насыщенность, метрики шрифта, предпросмотр и GIF timeline.
- Привязанные к UUID и группе сессии; черновики и коды с TTL, проверкой владельца и атомарным одноразовым применением.
- Постоянные Unicode glyphs, PNG atlas pages, Unicode-страницы для 1.12 или font JSON для 1.13+, pack format для версии сервера, ZIP/SHA-1, версии URL, предыдущие ревизии и rollback.
- TAB отдельно для каждого получателя с учётом подтверждённого resource pack; текстовый fallback, анимация готовых кадров, чат с состоянием pack каждого получателя.
- SQLite schema 3, миграция текстового ядра, сериализация изменений, кэш после commit, очистка временных файлов и повторное использование идентичных assets.
- Административный журнал в чат и файл, ротация, сохранение личного on/off, recent; status, glyphs, reload, pack-команды и права.

## Локальная сеть в 2.0.2

Редактор определяет активные IP сетевых интерфейсов компьютера с сервером и предпочитает подсеть игрового подключения. `/lptab linkwifi` показывает кликабельный список: выбор адреса открывает личную сессию редактора, `/lptab linkwifi auto` возвращает автоматический выбор. Выбор действует только для игрока, до двух часов, и сбрасывается при исчезновении адреса.

Если предпочтительный HTTP-порт занят, в автоматическом LAN-режиме выбирается свободный; ссылки редактора и ресурс-пака используют фактический порт. `web.port: 0` позволяет сразу выбрать порт средствами ОС. Явные внешние адреса сохраняют фиксированный порт. `doctor` и `status` показывают состояние HTTP, binding, порт и ошибку запуска.

Для устройств в одной локальной сети проброс порта роутера не требуется. Плагин не сканирует SSID и не подключает компьютер игрока к Wi-Fi: этим управляет ОС. Доступ из Интернета требует отдельного доступного адреса/proxy/туннеля. Подробная настройка и диагностика: [NETWORKING.md](docs/NETWORKING.md).

## Исправление ответов команд в 2.0.1

Ответы команд отправляются напрямую через Bukkit. Кликабельные сообщения используют Spigot SYSTEM с JSON-конвертацией; при недоступности rich API остаётся читаемый текст/URL. Состояние audience registry больше не влияет на доставку. Добавлены проверка реального MessageService и `/lptab doctor`: отчёт в чат и лог, включая версию, ядро и readiness.

При обновлении остановите сервер, замените единственный JAR TabPrefix в `plugins` и запустите сервер. Каталог данных и существующие YAML сохраняются. Если обычное имя команды конфликтует с другим плагином, используйте `/tabprefix:lptab doctor` и `/tabprefix:lptab help`.

## Установка готового JAR

1. Подготовьте Spigot, Paper или Purpur 1.12–1.21.11 либо 26.1–26.3. LuckPerms можно установить для интеграции групп и контекстов. Используйте Java по требованиям ядра: [COMPATIBILITY.md](docs/COMPATIBILITY.md).
2. Скопируйте **`dist/TabPrefix.jar`** из архива в `plugins` сервера и перезапустите сервер.
3. Проверьте `/lptab status`. Плагин создаст конфигурацию, оба файла сообщений, SQLite и служебные каталоги.
4. Для домашней сети оставьте `web.public-host`, `web.public-base-url` и `resource-pack.public-base-url` пустыми, `web.bind-address: "0.0.0.0"`, `web.auto-port: true`. Выполните `/lptab linkwifi`. Порт показан в ссылке; при необходимости разрешите его в брандмауэре компьютера с сервером. Для игроков из Интернета задайте доступный внешний URL и настройте сетевой доступ отдельно.
5. Для русского интерфейса установите `general.language: ru`. Адрес/порт требуют перезапуска; язык и обычные настройки перечитываются через `/lptab reload`.
6. Выдайте нужные права. По умолчанию обычный игрок имеет только `tabprefix.use`; редактор не открыт всем автоматически.

Пример выдачи доступа группе `vip` через LuckPerms:

```text
/lp group vip permission set tabprefix.user.* true
```

**Префикс принадлежит группе:** игрок с правами редактирования своей группы меняет отображение всех её участников. Выдавайте эти права тем, кому разрешено такое изменение. Выбор другой группы требует `tabprefix.prefix.manage`.

Для HTTPS задайте `web.public-base-url: "https://prefix.example.com"` и настройте reverse proxy к `127.0.0.1:8765`. Если resource pack отдаётся по другому внешнему адресу, используйте `resource-pack.public-base-url`. Внешний URL должен сохранять маршруты `/editor`, `/editor.js`, `/editor.css`, `/api/` и `/packs/`. Пример и диагностика: [эксплуатация](docs/OPERATIONS.md).

## Создание графического префикса

1. В игре выполните `/lptab webeditor`, откройте личную ссылку.
2. Загрузите PNG/JPEG/GIF, выберите область и обработку; при необходимости включите замену текстового префикса.
3. Изменения сохраняются и применяются автоматически. Дождитесь статуса «Сохранено и применено». «Сохранить сейчас» отправляет очередь сразу; код в игре вводить не нужно.
4. Выполните показанную команду `/lptab webpref ABCD-EFGH` до истечения кода.
5. Примите resource pack. Изображение показывается получателю только после `SUCCESSFULLY_LOADED`; до этого используется настроенный текстовый fallback. На 1.12 применяется Unicode pack с фиксированным размером глифа; при отсутствии исходного шрифта редактор сообщает ошибку и остаётся текстовый fallback.

Отключённый текстовый override использует префикс LuckPerms при доступной интеграции; в самостоятельном режиме текст задаётся своим override. Включённый override сохраняет собственный текст. Применение нового черновика заменяет обе части группового префикса: текстовый черновик без изображения убирает прежнее изображение, а изображение без override возвращает текст LuckPerms. Удаление через `webpref remove` убирает обе собственные части. Команда `prefix remove` удаляет только собственный текст.

GIF анимируется в TAB и name tags. Строка отправленного сообщения чата сохраняет кадр, выбранный при отправке; старые сообщения не перерисовываются.

## Команды и права

Все команды начинаются с `/lptab`; алиас — `/tabprefix`.

| Аргументы | Действие | Право |
|---|---|---|
| `help` | Доступная справка | `tabprefix.use` |
| `status` | Состояние модулей, assets и pack | `tabprefix.status` |
| `doctor` | Прямой диагностический ответ в чат и лог | `tabprefix.status` |
| `reload` | Перечитать настройки и сообщения | `tabprefix.reload` |
| `prefix set <group> [--mini\|--legacy] <text>` | Собственный текст группы | `tabprefix.prefix.manage` |
| `prefix info <group>` | Посмотреть текстовую запись | `tabprefix.prefix.manage` |
| `prefix remove <group>` | Убрать текстовый override | `tabprefix.prefix.manage` |
| `webeditor [group]` | Личная ссылка редактора; только из игры | `tabprefix.webeditor` |
| `linkwifi [IP\|auto]` | Список локальных интерфейсов и выбор адреса редактора | `tabprefix.webeditor` |
| `webpref <code>` | Применить сохранённый черновик; только из игры | `tabprefix.webpref` |
| `webpref info [group]` | Информация о префиксе группы | `tabprefix.webpref.info` |
| `webpref remove [group]` | Удалить собственный префикс группы | `tabprefix.webpref.remove` |
| `pack status` | SHA-1, страницы, glyphs, размер и URL | `tabprefix.pack.status` |
| `pack rebuild` | Пересобрать pack | `tabprefix.pack.rebuild` |
| `pack send [player\|all]` | Отправить активный pack | `tabprefix.pack.send` |
| `pack rollback <sha1>` | Активировать сохранённую ревизию | `tabprefix.pack.rollback` |
| `glyphs` | Использование диапазона glyphs | `tabprefix.pack.status` |
| `adminlog on\|off` | Личный вывод журнала в чат | `tabprefix.adminlog.toggle` |
| `adminlog recent [1..50]` | Последние записи журнала | `tabprefix.adminlog` |

Также нужен `tabprefix.use` для входа в команду. Явное указание группы в `webeditor`/`webpref info`/`webpref remove` дополнительно требует `tabprefix.prefix.manage`. Полные группы прав: `tabprefix.user.*`, `tabprefix.pack.*`, `tabprefix.adminlog.*`, `tabprefix.admin.*`. Административные права по умолчанию доступны OP. Без флага формат текстовой команды определяется автоматически; в одной записи используйте один формат. Префикс ограничен 512 единицами UTF-16, управляющие символы и переносы строк запрещены, включая MiniMessage `<newline>`.

Примеры:

```text
/lptab prefix set admin --mini <gold>[Admin]</gold>
/lptab prefix set vip --legacy &6[VIP]
/lptab webeditor vip
/lptab pack status
/lptab adminlog recent 10
```

## Лимиты и совместимость

По умолчанию: файл до 10 MiB, исходник до 4096×4096, суммарный бюджет обработки 128 миллионов пикселей, GIF до 100 кадров, media storage 512 MiB. Одна ячейка 32×16; метрики шрифта 16/13; atlas 512×512. Диапазон U+E000–U+F8FF содержит 6400 glyphs, GIF расходует по одному glyph на кадр. Изменение размеров и диапазона при уже назначенных assets требует сохранения совместимости; инициализация отклоняет несовместимые записи.

Назначенные glyphs не перераспределяются и их assets не удаляются при смене префикса: это сохраняет смысл старых строк и packs. Идентичные исходники, настройки и обработанные кадры используют один asset. Поэтому удаление префикса не освобождает ранее занятые codepoints. Откат pack меняет pack, сохраняя текущие групповые настройки; assets, отсутствующие в откатанном pack, получают fallback у загрузивших его клиентов.

Старый API resource pack, включая Minecraft 1.16, не передаёт ID pack в ответном событии. Плагин допускает один незавершённый запрос на игрока; новая ревизия ждёт его завершения. При timeout запрос сохраняется для корректного позднего ответа, повторить можно после переподключения. Если другой плагин одновременно отправляет собственный pack, события нельзя надёжно различить. Согласуйте одного отправителя и используемый pack; автоматического объединения чужих packs нет. На современных API используются отдельный UUID и снятие только собственных packs; чужие ответы с другим ID игнорируются.

Name tags и создание отдельного scoreboard по умолчанию выключены. Плагин не меняет чужую team игрока. На общем scoreboard изображение используется только если все его зрители загрузили asset. Плагины, одновременно управляющие TAB, teams или обработкой чата, требуют проверки совместной работы; графический чат использует `AsyncPlayerChatEvent` и доставку по получателям в основном потоке.

## Сборка из исходников

Нужны JDK 8 или новее, Bash, curl, unzip и `sha256sum` либо `shasum`. Maven и Gradle не используются. На Windows выполняйте shell-скрипты в окружении с этими утилитами.

```bash
bash build.sh
bash test.sh
bash build.sh --offline
bash test.sh --offline
# Дополнительная матрица требует JDK 17+ и Python 3:
bash test-compatibility.sh
bash clean.sh
bash clean.sh --all
```

Первая сборка скачивает закреплённые JAR-файлы по HTTPS и проверяет `dependencies.sha256`; `--offline` использует уже заполненный кэш. Обычная очистка сохраняет зависимости, `--all` удаляет их. Итоговый JAR содержит runtime-библиотеки, ресурсы и редактор. Spigot/LuckPerms API и build tools исключены. Adventure/Gson/SLF4J изолированы внутри плагина, SQLite сохраняет пакет для JNI. Лицензии вложенных библиотек находятся в `META-INF/licenses` итогового JAR; зависимости перечислены в `dependencies.conf`.
